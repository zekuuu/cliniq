Shared, generic UI components only — Button, Card, Badge, etc. at the design-system level (CLINIQ-Knowledge-Base/03-Design/Design-System.md). If it's specific to one feature, it belongs in that feature's folder instead, not here.

Toggles vs. views: `SegmentedControl` (an ARIA radiogroup) switches a setting inside a card, such as the calendar period or chart/table. `Tabs` (ARIA tabs, one size up) switches a whole page between views and keeps every panel mounted; with `printAll`, hidden panels still print (first use: the Dashboard, ADR-025). Its optional `actions` sit on the tab row: right of the tabs from `md` up, above them on narrower screens, so the tabs always sit directly over their panel (Dashboard: Staff's New Visit).

Printouts: `print/Print.tsx` holds the shared A4 document parts and the one `PrintButton` (disabled, with its reason underneath, for the Admin, who never prints, and for a not-yet-printable document such as a draft letter; ADR-038) (`PrintDocument`, `PrintSection`, `PrintTable`, `PrintFigures`, `PrintBars`, `PrintFields`, `PrintSignatures`, `PrintNote`). `PrintDocument` mounts only while the browser prints (`hooks/usePrinting.ts`), renders into `document.body`, and writes the printed-by footer and page numbers into the `@page` margin boxes; `index.css` hides the app for that print (ADR-026, `cliniq-print-patterns`). The Dashboard still passes `printAll`, but its printout is the Clinic Overview Report, so its tab panels no longer reach paper.

Other folders: `ui/` (the design-system pieces, including `BackButton`, `Select`, `Combobox`, `MultiSelect`, `DatePicker`, `DateRangePicker`, `DataTable`, `Pagination`, `Modal`), `forms/` (`StudentPicker`, `InventoryItemPicker`, `ItemsGivenField`, `FollowUpPrompt`), `charts/`, `status/`, `icons/`. Each has a `cliniq-*-patterns` skill where one exists (`04-Development/Skills-Setup.md`). `KeyboardShortcuts` holds the app-wide shortcuts (`Alt + N` New Visit, `Alt + I` Report Incident, `?` for the list).
