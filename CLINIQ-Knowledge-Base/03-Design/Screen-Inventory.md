## 4. Complete Page/Screen Inventory

Give the agent this full list — it maps directly to the two module groups (baseline + enhancements) already finalized in planning.

### Auth & Shell
1. **Login** — username/password, role-aware redirect after login; the session lasts 1 week until the token expires, with no idle timeout
2. **Force Password Change** — shown on first login (backend enforces this)
3. **App Shell/Nav** — role-aware sidebar or nav; Staff sees all modules, Admin sees Dashboard, Calendar, Reports and Audit Log, Instructor sees only the mobile scan/lookup screen (no shell/nav needed for that one). The desktop header shows the signed-in user's name and role with a red, icon-only Log out control carrying an accessible label.

### Dashboard
4. **Staff Dashboard** — today's visit count, low-stock alerts, expiring-medicine alerts, backup status widget, quick "New Visit" action. Delivered on the shared Clinic Overview (#31): Staff get a strip under the header with the "New Visit" action and a backup-status indicator (status + last-backup date) linking to #32
5. **Admin Dashboard** — summary cards linking into Reports and the Clinic Overview Dashboard (no edit actions)

### Student Records
6. **Student List** — searchable/filterable table (name, grade level, flags for incomplete records)
7. **Student Profile (view)** — full record: demographics, medical history, allergies, emergency contact, visit history for that student
8. **Add/Edit Student** — form with required-field validation (full name, grade level, emergency contact, allergies, conditions); triggers duplicate-detection warning on save
9. **Incomplete Records Review Queue** — list of Registrar-imported records flagged incomplete, with who-resolved-it tracking

### Clinic Visit Monitoring
10. **Visit Log List** — daily/date-filterable list of visits; shows **Student Number**, not full name, per the display-privacy rule (a multi-student list, not a single deliberate lookup). Header has a primary **New Visit** button (→ #11)
11. **New Visit Entry** — student lookup, complaint, **Treatment notes**, **Medicines & supplies given** (searchable inventory picker + repeatable lines with quantity stepper, unit, optional instructions; recorded allergies shown beside the picker; ADR-018), disposition (returned to class / sent home / referred to hospital); **this is where the Smart Triage checklist panel appears** once a complaint is selected. Notes or at least one line is required
12. **Visit Detail/Edit** — shows treatment notes and the medicines given ("Paracetamol 500mg × 2 tablets (1 tablet every 6 hours)"); editing the lines adjusts stock through "visit edited" adjustments (ADR-018)
13. **Excuse Letter Generator** — pulls from a visit record, produces a printable letter; nurse checks and approves it, then it's stored permanently in the student's record as a printable document. **Medical certificates are out of scope** — those are hospital-issued, never generated by CLINIQ; don't conflate the two in the UI or data model
14. **PE/Sports Injury Referral Form** — logs referral, links into the same visit/treatment flow

### Emergency Response
15. **Incident Log List** — shows which incidents are still Stage-1 (fast-capture, incomplete) vs fully completed; shows **Student Number**, not full name, per the display-privacy rule. Header has a primary **New Incident** button (→ #16, Stage 1)
16. **New Incident Entry — Stage 1 (fast capture)** — student, complaint, immediate vitals only; saves immediately, speed over completeness
16b. **Incident Entry — Stage 2 (complete later)** — same record, opened afterward to fill in full vitals, treatment notes, hospital referral fields (destination, transport, departure time)
17. **Parent Notification Outcome Logging** — timestamped, tied to the incident (Reached / Not Reached / Voicemail / Left Message)
18. **Incident Report View/Print** — generated summary for the nurse to review, sign, and print

### Follow-Up Handling (feature spanning Clinic Visit Monitoring + Emergency Response)
18b. **Follow-Up Prompt (Staff)** — appears inline at the end of saving #11 (New Visit Entry) or #16 (Incident Entry, Stage 1): "Does this student need a follow-up?" If yes, capture follow-up date, reason/instruction, and optional notes in the same flow — not a separate screen Staff has to remember to visit afterward
18c. **Follow-Up List View (Staff)** — all follow-ups, filterable by status (Pending / Completed / Missed / Cancelled); each pending row has one status control to mark it Completed, Missed, or Cancelled (Missed and Cancelled ask for confirmation; Completed, the expected outcome, does not). Shows **Student Number**, not full name, per the display-privacy rule (multi-student list). There is no separate follow-up detail screen

### Reports Generation
19. **Monthly Report View/Generate**
20. **Incident Report Archive**
21. **Health Summaries View**
(All three need print/export-friendly layouts — this is a paper-replacement feature, so print CSS matters.)

### QR Digital Health ID (enhancement) — computer (Staff) + mobile (Staff and PE/Sports Instructor)
22. **QR Code Print View** — generates/prints a QR sticker per student, encoding their Student Number (Staff only, computer)
23. **Scan/Lookup Hub (Staff, computer or mobile)** — two ways to identify a student: "Scan QR Code" (camera) or "Enter Student Number" (manual text fallback); once identified, shows the student's full name and details normally — this is a deliberate single-student lookup, not a glanceable list (see the display-privacy rule)
24. **Student Quick-Actions (Staff)** — appears once a student is identified: **Record Visit** (→ #11, pre-filled), **Log Emergency** (→ #16, Stage 1, pre-filled), **View Full Profile** (→ #7), **Dispense Medicine** (→ #30, pre-linkable to the visit), **PE/Sports Referral** (→ #14, pre-filled — this is #14's entry point)
25. **Emergency Button (Staff, mobile)** — separate, faster entry point than the quick-actions above; jumps straight to #16 (Stage 1) rather than routing through student identification first if a scan already happened
26. **Instructor Scan/Lookup (PE/Sports Instructor, mobile only)** — scan or enter a Student Number; opens a **read-only** view of that student's full profile plus visit/incident history. No buttons for any action — this screen only displays data

No separate login screen for Staff here — the computer and mobile Staff flows both run inside the existing Staff session. The Instructor flow does need its own login (Instructor role), since it's a different account type, but it's still a normal auth-gated screen, not a public/unauthenticated one — nothing in this system is reachable without logging in as something.

### Smart Triage Quick-Reference (enhancement)
27. Not a standalone page — a checklist panel/modal embedded in **New Visit Entry** (#11), triggered by the selected complaint type

### Medicine & Supply Inventory Tracker (enhancement)
28. **Inventory List** — items, current stock, expiration dates, low-stock/expiring flags. Row actions: **Restock** (modal: quantity received + expiration date), **Adjust Stock** (modal: +/- change or set to counted quantity, required reason, optional note, never below 0), **Edit** (ADR-018)
29. **Add/Edit Inventory Item** — on Edit, current stock and expiration date are read-only (they change only through Dispense/Restock/Adjust Stock)
30. **Dispense/Log Usage** — for non-visit use; must name a student or choose "Not for a student (general use)"; shows a notice linking to the student's visit today when one exists; expired items can't be picked (ADR-018)

### Clinic Overview Dashboard (enhancement, expanded from "Health Trends Dashboard"; Staff + Admin-facing)
31. **Dashboard View** — Overview starts with visit, incident, active-student, pending-excuse-letter, and due/overdue-follow-up totals; Inventory and incomplete-record attention counts drill through for Staff; Frequent visitors appear lower. Trends keep date-derived grouping, Chart/Table fallback, symptom clustering, and display-private frequent-visitor warnings.
31a. **Clinic Calendar** — Staff and Admin top-level calendar with Weekly/Monthly/Yearly and Calendar/Table controls, holidays, visit/incident tags, and Staff-only school-event management (ADR-019, ADR-020).

### Backup Verification Assistant (enhancement)
32. **Backup Status Screen** — last backup date/size/status, plus a plain-language guided recovery checklist (Staff-only, likely nurse-only)

### User Management
33. **User List** — Staff only; Staff, Admin/Principal, and PE/Sports Instructor accounts
34. **Add/Edit User & Role Assignment**

### Audit Log Viewer
35. **Audit Log** — Staff and Admin/Principal, view-only; filterable by date range, user, action type, and target/module (`ADR-016`); Student Number not name for student-related entries, per the display-privacy rule

### Sidebar Footer / Legal
36. **Privacy Policy** — accessible to every role (Staff, Admin/Principal, PE/Sports Instructor), reached via a link in the sidebar footer; static content, no student data rendered on the page itself. Draft content: `09-References/Privacy-Policy.md`.

**Total: ~37 screens/views** (accounting for the two-stage incident entry and the new Instructor and Emergency-button screens), several of which (Excuse Letter, Incident Report, Monthly Report, QR print) also need a distinct print layout — call that out to the agent explicitly since print CSS is easy to forget.
